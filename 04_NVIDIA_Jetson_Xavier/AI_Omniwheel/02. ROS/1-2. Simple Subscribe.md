# 1-2. ROS Simple Subscribe

## 1. 학습 목표

- **Subscriber(구독자)** 의 동작 방식을 이해한다.
- `chatter` 토픽에서 수신한 문자열을 **콜백(callback)** 으로 처리한다.
- 1-1(Publisher)과 함께 Topic 통신의 발행/구독 구조를 완성한다.

## 2. 준비 사항

### 2.1 필요 하드웨어

- NVIDIA Jetson Xavier NX (ROS Melodic 설치 완료)

### 2.2 필요 라이브러리

- ROS 1 Melodic (`rospy`, `std_msgs`), Jupyter Notebook

### 2.3 사전 설정

```bash
$ source /opt/ros/melodic/setup.bash
$ roscore
$ jupyter notebook
```

## 3. 실행 방법

1. 터미널에서 `roscore` 실행.
2. `02. ROS/1-2. Simple Subscribe.ipynb` 오픈 후 셀을 순서대로 실행.
3. **발행자는 이 노트북에 없으므로**, 아래 두 가지 중 하나로 발행자를 준비:
   - 방법 A: `1-1. Simple publish.ipynb`(발행 셀)를 실행한 상태로 두고 이 노트북 실행
   - 방법 B: 터미널에서 `rostopic pub -r 10 /chatter std_msgs/String "hello"` 실행
4. 콜백이 수신한 메시지가 노트북 출력에 표시되면 성공.

## 4. 코드 해설

### 1) 모듈 추가

```python
import rospy
from std_msgs.msg import String
```

- 발행자와 동일하게 `rospy`와 `std_msgs.msg.String`을 사용한다. (같은 토픽/같은 타입이어야 수신 가능)

### 2) 데이터 수신 처리(콜백) 함수

```python
def callback(data):
    rospy.loginfo(rospy.get_caller_id() + "I heard %s", data.data)
```

| 요소 | 설명 |
| ---- | ---- |
| `callback(data)` | 토픽으로 메시지가 도착할 때마다 자동 호출되는 함수 |
| `data` | 수신한 `String` 메시지 객체 |
| `data.data` | `String` 메시지 안의 실제 문자열 값 |
| `rospy.get_caller_id()` | 이 노드의 이름(예: `/listener`) 반환 |
| `rospy.loginfo(...)` | 수신 내용을 로그로 출력 |

> 콜백은 사용자가 직접 호출하지 않는다. Subscriber가 메시지를 받을 때 ROS가 자동으로 호출한다.

### 3) 노드 생성

```python
rospy.init_node('listener', anonymous=True)
```

- `listener` 노드를 생성한다.

### 4) Subscriber 객체 생성

```python
rospy.Subscriber("chatter", String, callback)
```

- `chatter` 토픽에서 `String` 타입을 구독하고, 도착 시 `callback`을 호출하도록 등록한다.

> ⚠️ 이 노트북에는 **`rospy.spin()`이 없습니다.** `spin()`이 없으면 콜백이 실행될 스레드가
> 마련되지 않아 수신 처리가 안 될 수 있습니다. 셀 마지막에 다음을 추가하면 안정적으로 동작합니다.

```python
rospy.spin()    # 메시지가 올 때까지 대기하며 콜백을 처리
```

## 5. 실행 결과 예시

```
[INFO] [1659427200.123456]: /listener I heard hello world 1659427174.5283244
[INFO] [1659427201.234567]: /listener I heard hello world 1659427174.6289130
```

## 6. 주의사항 및 트러블슈팅

| 증상 | 원인/해결 |
| ---- | --------- |
| 메시지가 출력되지 않음 | `spin()` 누락 → 추가 후 재실행 |
| 발행자가 없어 수신 불가 | 발행자 실행 확인 (`rostopic pub` 또는 1-1 노트북) |
| 타입 불일치 오류 | 토픽 이름·메시지 타입(`String`) 일치 확인 |
| `ROS_MASTER_URI` 오류 | `roscore` 실행 여부 확인 |

## 7. 실습 과제

1. 콜백 안에서 메시지 수신 횟수를 세어 10번마다 "10 messages received" 출력.
2. `chatter`가 아닌 `my_topic`으로 구독해 보고, 발행자와 토픽 이름이 다르면 수신이 안 되는 것을 확인.
3. `data.data`를 대문자로 변환(`data.data.upper()`)해서 출력해 보기.
