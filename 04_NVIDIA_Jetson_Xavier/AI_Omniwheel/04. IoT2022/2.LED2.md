# 2. LED2 밝기 램프 (PWM duty_cycle을 이용한 페이드 인/아웃)

## 1. 학습 목표
- PCA9685의 `duty_cycle` 값을 연속적으로 변화시켜 LED 밝기를 서서히 제어하는 방법을 익힌다.
- PWM(Pulse Width Modulation)의 듀티비 개념을 이해한다.
- 12비트(0~4095) 해상도의 동작 원리를 이해한다.
- 중첩 `for` 루프와 짧은 `time.sleep()`의 역할을 이해한다.

### 1.1 배경 지식: 페이드 효과의 원리
- 사람의 눈은 밝기 변화를 일정 임계점 이상의 단계 차이에서만 인식한다. duty를 0→4095로 1씩 4096단계로 변화시키면 밝기 차이가 매우 작아 **부드러운 페이드 인**처럼 보인다.
- 외부 루프(`duty`)와 내부 루프(`index`)의 중첩 구조에서, 내부 루프가 한 번 돌 때마다 모든 채널에 같은 duty가 적용된다. 즉 8개 LED가 **동시에** 같은 밝기로 변한다.
- 페이드 인은 0.0005초×8 = 0.004초/단계라 빠르고, 페이드 아웃은 0.005초×8 = 0.04초/단계라 10배 느리다. 이 차이가 "천천히 어두워지는" 램프 효과를 만든다.

## 2. 준비 사항
### 2.1 필요 하드웨어
- NVIDIA Jetson Xavier NX 보드 (JetPack 4.x)
- PCA9685 PWM 드라이버 모듈 (I2C 주소 0x40)
- LED 8개 (PWM 채널 0 ~ 7)

### 2.2 필요 라이브러리 (설치 명령 포함)
```bash
sudo pip3 install adafruit-circuitpython-pca9685
```

### 2.3 사전 설정
- PCA9685의 SCL/SDA를 Jetson의 **SCL_1 / SDA_1** 핀에 연결한다.
- LED는 채널 0~7에 연결한다.
- 1.LED 실습이 먼저 동작하는지 확인해 PCA9685와 배선이 정상임을 점검한다.

### 2.4 실행 시간 예상
- 페이드 인: 4096단계 × 0.004초 ≈ 16.4초
- 페이드 아웃: 4096단계 × 0.04초 ≈ 163.8초 (약 2.7분)
- 페이드 아웃이 상당히 길므로, 원한다면 중간에 셀을 정지시키며 실험해도 좋다.

## 3. 실행 방법 (셀 실행 순서 안내)
1. 필요한 모듈 import
2. I2C 객체 생성, PCA9685 초기화, 주파수 60Hz 설정
3. `duty`를 0→4095로 올리며 8개 LED 밝기를 서서히 증가 (페이드 인)
4. `duty`를 4095→0으로 내리며 8개 LED 밝기를 서서히 감소 (페이드 아웃)

셀을 실행하면 LED가 아주 천천히 밝아졌다가 어두워지는 램프 효과가 한 번 나타난다.

**단계별 예상 확인 포인트**
- 실행 직후 8개 LED가 동시에 아주 살짝 밝아지기 시작한다.
- 페이드 인(~16초) 동안 밝기가 눈에 띄게 상승한다.
- 페이드 아웃(~2.7분) 동안 밝기가 서서히 내려가고, LED가 켜진 채로 오래 유지된다.
- 전체가 끝나면 모든 LED가 꺼진 상태가 된다.

**중단 방법**: 페이드 아웃이 길므로 중간에 정지(■) 버튼을 눌러도 된다.

## 4. 코드 해설 (원본 코드 그대로)
```python
import busio
import board
import adafruit_pca9685
import time
i2c = busio.I2C(board.SCL_1, board.SDA_1)
pca9685 = adafruit_pca9685.PCA9685(i2c)
pca9685.frequency = 60
for duty in range(0, 4096):
    for index in range(0, 8):
        pca9685.channels[index].duty_cycle = duty
        time.sleep(0.0005)
for duty in range(4095, -1, -1):
    for index in range(0, 8):
        pca9685.channels[index].duty_cycle = duty
        time.sleep(0.005)
```

**줄 단위 해설**
- `import busio / board / adafruit_pca9685 / time`: I2C 버스, 핀 정의, PCA9685 드라이버, 지연 함수 사용을 위한 import.
- `i2c = busio.I2C(board.SCL_1, board.SDA_1)`: SCL_1/SDA_1 핀으로 I2C 버스 초기화.
- `pca9685 = adafruit_pca9685.PCA9685(i2c)`: PCA9685(0x40) 드라이버 객체 생성.
- `pca9685.frequency = 60`: PWM 주파수 60Hz 설정.
- `for duty in range(0, 4096):`: duty 값을 0부터 4095까지 1씩 증가. 총 4096단계의 밝기 제어.
- `for index in range(0, 8):`: 8개 채널(0~7)에 동일한 duty를 적용하는 중첩 루프.
- `pca9685.channels[index].duty_cycle = duty`: 현재 duty 값으로 해당 채널 밝기를 설정. 0이면 OFF, 4095면 최대 밝기.
- `time.sleep(0.0005)`: 0.5ms 대기. 한 채널당 0.0005초 × 8채널 = 한 duty 단계에 약 0.004초가 소요되어 부드러운 페이드 인이 된다.
- `for duty in range(4095, -1, -1):`: duty를 4095부터 0까지 1씩 감소 (페이드 아웃).
- `time.sleep(0.005)`: 5ms 대기. 페이드 인(0.0005)보다 10배 느려서 어두워지는 속도가 눈에 띄게 느리다.

**동작 요약**: 4096단계의 duty 값을 8개 LED에 동시에 적용해 밝기가 점진적으로 올라가고 내려간다. 1번 실습(LED)이 ON/OFF였다면, 이번 실습은 '밝기의 아날로그적 제어'다.

**동작 흐름 정리**
| 순서 | 루프 | duty 변화 | sleep | 효과 |
| --- | --- | --- | --- | --- |
| 1 | `range(0, 4096)` | 0 → 4095 (증가) | 0.0005초 | 부드러운 페이드 인 |
| 2 | `range(4095, -1, -1)` | 4095 → 0 (감소) | 0.005초 | 느린 페이드 아웃 |

- duty가 1 증가할 때마다 8개 채널이 모두 갱신되므로, 채널별 0.0005초 → 한 단계에 0.004초가 걸린다.
- 페이드 아웃은 한 단계에 0.04초가 걸려 10배 느리다.

## 5. 원본 코드의 오타/수정 안내
이 노트북의 코드는 **오타 없이 정상 동작**한다.

참고 사항(필수 아님):
- 페이드 인과 페이드 아웃의 `sleep` 값(0.0005 vs 0.005)이 서로 다른 것은 의도된 속도 차이다. 동일한 속도를 원하면 두 값을 같게 맞추면 된다.
- `range(0, 4096)`은 4095까지, `range(4095, -1, -1)`은 0까지 포함하므로 duty 범위가 완벽하게 대칭이다.

**학습 포인트 요약**
- duty_cycle이 0~4095 사이의 **연속값**을 가지면 LED 밝기가 아날로그처럼 제어된다는 점이 핵심이다.
- 중첩 `for` 루프에서 외부 루프(duty)가 한 번 돌 때마다 내부 루프가 8채널을 갱신한다.
- sleep 값이 페이드 속도를 결정하며, 1.LED(ON/OFF)와 2.LED2(페이드)의 차이를 이해한다.
- 4096단계의 부드러운 변화는 I2C 통신이 정상일 때만 보인다. 통신 오류 시 밝기가 뚝뚝 끊긴다.

## 6. 실행 결과 예시
- 터미널 출력 없음, LED 밝기 변화를 육안으로 확인한다.
- 관찰 결과:
  - 페이드 인: 8개 LED가 동시에 아주 부드럽게 밝아진다 (약 1~2초).
  - 페이드 아웃: 8개 LED가 서서히 어두워진다 (약 5~10초).
- 밝기가 불연속적으로 튀는 듯 보이면 I2C 버스 부하(주파수, 케이블 길이)를 확인한다.

**시간별 밝기 예시** (duty 값 기준)
| 시점 | duty (밝기) | 상태 |
| --- | --- | --- |
| 시작 | 0 | 전부 OFF |
| 1.6초 후 | 409 | 10% |
| 8초 후 | 2048 | 50% (절반) |
| 16초 후 | 4095 | 100% (최대) |
| 60초 후 | ~3072 | 75% (감소 중) |
| 약 2.7분 | 0 | 전부 OFF |

- 위 시간은 sleep 0.0005/0.005 기준의 대략적 값이다.

## 7. 주의사항 및 트러블슈팅
- **듀티비 해상도**: PCA9685는 12비트(0~4095)이다. 4095 초과 값은 에러를 발생시키므로 `range` 경계를 주의한다.
- **I2C 버스 차이**: `board.SCL_1/SDA_1`을 사용한다. 버스 인식 오류 시 01. Device 버전(`board.SCL/SDA`)과 혼동하지 않도록 코드와 배선을 확인한다.
- **장치 미검출**: `sudo i2cdetect -y -r 1`로 0x40 검색 여부 확인.
- **실행 시간**: 페이드 아웃 단계가 상대적으로 오래 걸리므로, 중단하려면 Jupyter 정지 버튼을 사용한다.
- **밝기 변화가 안 보이는 경우**: 주변 조명이 밝으면 변화가 잘 안 보인다. 어두운 곳에서 확인한다.
- **I2C 통신 부하**: 4096×8회의 `duty_cycle` 쓰기는 I2C 트래픽이 많다. 케이블이 길거나 노이즈가 많으면 통신 오류가 날 수 있으니 배선을 짧게 유지한다.
- **듀티 소수점**: `duty_cycle`은 정수여야 하므로 `2047.5` 같은 값을 넣으면 오류가 난다. 정수 범위만 사용한다.
- **밝기가 안 변하는 경우**: `range(0, 4096)`이 아니라 `range(0, 4096, 1)`로 쓰거나, 내부 루프의 채널 범위가 잘못됐는지 확인한다. duty 갱신이 한 번만 일어나면 계단식으로 보인다.
- **특정 채널만 켜지지 않음**: 해당 채널 배선(납땜, LED 극성) 문제일 가능성이 높다. 1.LED로 채널별 점등을 먼저 확인한다.
- **일부 LED가 반대로 동작**: LED 극성(+/-)이 반대로 꽂혀 있으면 duty 0일 때 켜진 것처럼 보인다. 극성을 확인한다.

## 8. 실습 과제
1. 페이드 인/아웃의 `sleep` 값을 각각 0.001, 0.001로 바꿔 속도 변화를 비교하라.
   - 힌트: 두 루프의 sleep을 같게 하면 밝아지고 어두워지는 속도가 대칭이 된다.
2. 채널 0~3까지만 램프가 동작하도록 루프를 수정하라.
   - 힌트: 내부 루프를 `for index in range(0, 4):`로 바꾼다.
3. duty를 0에서 4095로 가되 3단계씩 점프(step 3)하도록 `range(0, 4096, 3)`으로 바꿔 실행하라.
   - 힌트: step을 키우면 단계 수가 줄어 밝기가 계단식으로 변하는 것이 보인다.
4. 밝아졌다 어두워지는 동작을 3회 반복하도록 `while` 루프로 감싸 보라.
   - 힌트: `for repeat in range(3):` 안에 두 루프를 넣으면 된다.
5. 채널마다 서로 다른 duty(예: 채널 0은 최대, 채널 7은 최소)를 설정하는 코드를 작성하라.
   - 힌트: 내부 루프에서 `duty_cycle = duty * (index + 1) // 8`처럼 채널별 배율을 곱해보자.
6. 페이드 인만 3회 반복하고 페이드 아웃 없이 마지막에 전등을 끄는 코드를 작성하라.
   - 힌트: 페이드 인 루프만 `for`로 감싸고, 끝나면 전체 duty를 0으로 설정한다.
7. duty를 2048(50%)로 고정하고 0.2초 간격으로 깜빡이는 코드를 작성하라.
   - 힌트: `duty_cycle`을 2048과 0으로 번갈아 설정하면 된다.
8. 페이드 인 도중 duty가 1024일 때 잠시 멈추는(1초 대기) 코드를 작성하라.
   - 힌트: `if duty == 1024: time.sleep(1)`을 내부 루프에 추가한다.
