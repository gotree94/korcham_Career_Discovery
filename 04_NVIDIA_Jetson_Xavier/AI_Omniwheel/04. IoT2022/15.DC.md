# 15. DC 모터 제어 (옴니휠 속도 명령)

## 1. 학습 목표
- 직렬통신으로 옴니휠 로봇의 **DC 모터 3개(X/Y/Z)를 제어**하는 방법을 익힌다.
- 모터 제어 명령 **CONTROL_DRIVE(0xC0)** 와 MID 0x80(X)/0x81(Y)/0x82(Z)를 이해한다.
- 모터 속도 값의 범위(약 -600 ~ 600)와 회전 방향(부호)의 의미를 배운다.
- 함수 정의와 메인 루프의 **구조 분리**(함수 안에 무한루프가 있어 생기는 문제)를 고치는 방법을 익힌다.

## 2. 준비 사항
### 2.1 필요 하드웨어
- NVIDIA Jetson Xavier NX 보드 (JetPack 4.x)
- Arduino 보드(옴니휠 드라이버) + USB 케이블
- DC 모터 3개 (옴니휠 X/Y/Z축) + 모터 드라이버

### 2.2 필요 라이브러리 (설치 명령 포함)
```bash
sudo pip3 install pyserial
```
- `Omniwheel_Protocol.py`: `01. Device\libraries\` 아래에 있다. IoT2022 폴더로 복사하거나 해당 폴더가 현재 경로에 있어야 한다.

### 2.3 사전 설정
- 포트 확인: `ls /dev/ttyUSB0`
- **포트 권한 부여**: `sudo chmod 777 /dev/ttyUSB0`
- 이 IoT2022 버전은 **`/dev/ttyUSB0`, 9600** 사용. (01. Device 버전은 `/dev/ttyACM0`, 115200)
- 로봇을 **들어 올린 상태**(바퀴가 공중에 떠 있는 상태)에서 실험한다. 제어 실수로 로봇이 갑자기 움직여도 안전하도록 한다.

## 3. 실행 방법 (셀 실행 순서 안내)
1. 모듈 import 및 상수 정의 (CONTROL_DRIVE, MID_list, Moter_Control 시퀀스)
2. 시리얼 열기(/dev/ttyUSB0, 9600), "connect complete" 확인
3. 모터 제어용 `Packet_send` 함수 정의
4. **메인 루프**: 모터 제어 값 시퀀스 `[600, 0, -600, 0]`을 순회하며 X/Y/Z에 순차 전송

**중요**: 원본 코드는 `_date`→`_data` 오타, `addPayload(_mid, _data)` 참조 문제, 그리고 **`while` 루프가 함수 안에 있어 무한 재귀**로 잘못 동작한다. 반드시 5번의 수정 코드를 사용한다.

## 4. 코드 해설 (원본 코드 그대로)
```python
import Omniwheel_Protocol
import serial
import time
Arduino_ID=0x20
CONTROL_DRIVE = 0xC0
MID_CONTROL_X_LINEAR_VELOCITY =0x80
MID_CONTROL_Y_LINEAR_VELOCITY =0x81
MID_CONTROL_W_ANGULAR_VELOCITY =0x82
MID_list=[MID_CONTROL_X_LINEAR_VELOCITY,
          MID_CONTROL_Y_LINEAR_VELOCITY,
          MID_CONTROL_W_ANGULAR_VELOCITY
          ]
Moter_Control = [600, 0, -600, 0]
send_packet = Omniwheel_Protocol.Packet()
send_packet.clearPacket()
Serial_Arduino = serial.Serial(port="/dev/ttyUSB0", baudrate =9600, timeout=.1)
time.sleep(1)
print("connect complete")

def Packet_send(_id, _cmd, _mid, _date):
    send_packet.clearPacket()
    send_packet.setID(_id)
    send_packet.setCMD(_cmd)
    send_packet.clearPayload()
    send_packet.addPayload(_mid, _data)
    send_packet.calcLRC_Lower()
    send_list=send_packet.packetToList()
    Serial_Arduino.write(send_list)
    while(True):
        for data in Moter_Control:
            for mid in MID_list:
                Packet_send(Arduino_ID, CONTROL_DRIVE, mid, data)
                time.sleep(1.0)
```

**줄 단위 해설**
- `import Omniwheel_Protocol / serial / time`: 프로토콜, 시리얼, 지연 모듈.
- `Arduino_ID=0x20`: Arduino ID.
- `CONTROL_DRIVE = 0xC0`: 모터 구동 제어 명령.
- `MID_CONTROL_X_LINEAR_VELOCITY = 0x80`: X축(전후) 선속도 제어 MID.
- `MID_CONTROL_Y_LINEAR_VELOCITY = 0x81`: Y축(좌우) 선속도 제어 MID.
- `MID_CONTROL_W_ANGULAR_VELOCITY = 0x82`: Z축(회전, 각속도 W) 제어 MID.
- `MID_list = [0x80, 0x81, 0x82]`: 3개 축 MID 리스트.
- `Moter_Control = [600, 0, -600, 0]`: 실행할 모터 속도 시퀀스. 600 = 정방향 최대, 0 = 정지, -600 = 역방향 최대. (옴니휠 로봇의 모터 명령 범위는 약 -600~600)
- `send_packet = Omniwheel_Protocol.Packet()` / `send_packet.clearPacket()`: 송신 패킷 객체 및 초기화.
- `Serial_Arduino = serial.Serial(port="/dev/ttyUSB0", baudrate=9600, timeout=.1)`: 시리얼 열기.
- `time.sleep(1) / print("connect complete")`: 연결 대기 및 확인.
- `def Packet_send(_id, _cmd, _mid, _date):`: 모터 제어 패킷을 만들어 보내는 함수.
  - **오타 1**: 파라미터 이름이 `_date`인데 함수 본문에서는 `_data`를 사용 → `NameError: name '_data' is not defined` 발생.
  - **오타 2**: `send_packet.addPayload(_mid, _data)`는 `_data`를 참조하지만 파라미터는 `_date`다.
  - **구조 오류**: `while(True):` 루프가 **함수 내부**에 있다. 이 함수는 모듈 레벨에서 호출된 적이 없으므로 실제로는 아무것도 실행되지 않고, 설령 호출돼도 `Packet_send`가 자기 자신을 재귀 호출하는 무한 루프에 빠진다.
- `for data in Moter_Control:`: 시퀀스 [600, 0, -600, 0]을 순회.
- `for mid in MID_list:`: X/Y/Z 축 순서로 제어.
- `Packet_send(Arduino_ID, CONTROL_DRIVE, mid, data)`: 해당 축에 속도 값 전송.
- `time.sleep(1.0)`: 1초 간격으로 명령 전송.

**동작 요약(의도)**: 모터를 600으로 1초 구동 → 정지 → -600으로 역구동 → 정지하는 동작을 X/Y/Z 축에 순차 적용한다.

## 5. 원본 코드의 오타/수정 안내
원본에는 **3가지 문제**가 있다.

**문제 1: 파라미터 `_date` → `_data` 오타**
- 수정 전: `def Packet_send(_id, _cmd, _mid, _date):`
- 수정 후: `def Packet_send(_id, _cmd, _mid, _data):`
- 수정하지 않으면 `addPayload(_mid, _data)` 줄에서 `NameError`가 발생한다.

**문제 2: `addPayload(_mid, _data)` 참조**
- 파라미터를 `_data`로 고치면 `_data` 참조가 해결된다.

**문제 3: `while(True)` 루프가 함수 안에 있음 (무한 재귀 구조)**
- 수정 전: `while(True):` 루프가 `Packet_send` 함수 안에 중첩되어 있고, 함수가 모듈 레벨에서 호출되지 않으므로 동작하지 않는다.
- 수정 후: 함수 정의는 **송신만** 담당하고, `while(True)` 메인 루프는 **함수 밖(모듈 레벨)** 에 둔다.

**수정 코드 (전체)**:
```python
import Omniwheel_Protocol
import serial
import time

Arduino_ID = 0x20
CONTROL_DRIVE = 0xC0
MID_CONTROL_X_LINEAR_VELOCITY = 0x80
MID_CONTROL_Y_LINEAR_VELOCITY = 0x81
MID_CONTROL_W_ANGULAR_VELOCITY = 0x82
MID_list = [MID_CONTROL_X_LINEAR_VELOCITY,
            MID_CONTROL_Y_LINEAR_VELOCITY,
            MID_CONTROL_W_ANGULAR_VELOCITY]
Moter_Control = [600, 0, -600, 0]
send_packet = Omniwheel_Protocol.Packet()
send_packet.clearPacket()
Serial_Arduino = serial.Serial(port="/dev/ttyUSB0", baudrate=9600, timeout=.1)
time.sleep(1)
print("connect complete")

def Packet_send(_id, _cmd, _mid, _data):
    send_packet.clearPacket()
    send_packet.setID(_id)
    send_packet.setCMD(_cmd)
    send_packet.clearPayload()
    send_packet.addPayload(_mid, _data)
    send_packet.calcLRC_Lower()
    send_list = send_packet.packetToList()
    Serial_Arduino.write(send_list)

while(True):
    for data in Moter_Control:
        for mid in MID_list:
            Packet_send(Arduino_ID, CONTROL_DRIVE, mid, data)
            time.sleep(1.0)
```
(핵심 수정: `_date`→`_data`, `while` 루프를 함수 밖으로 이동)

## 6. 실행 결과 예시
- 터미널 출력은 "connect complete"뿐이다.
- 로봇 바퀴 동작 관찰:
  1. X축 바퀴가 정방향(600)으로 1초 구동
  2. 정지(0) 1초
  3. 역방향(-600)으로 1초 구동
  4. 정지(0) 1초
  5. 이 패턴이 X→Y→Z축 순서로 반복된다.
- 모터가 움직이지 않으면 Arduino 연결과 모터 드라이버 전원을 확인한다.

## 7. 주의사항 및 트러블슈팅
- **수정 필수**: `_date`→`_data` 오타와 무한 루프 구조를 반드시 고친다.
- **안전**: 바퀴가 공중에 뜬 상태에서 실험한다. 로봇이 갑자기 움직일 수 있다.
- **속도 범위**: 값은 -600~600 범위를 사용한다. 범위를 크게 벗어나면 Arduino 스케치가 무시하거나 이상 동작할 수 있다.
- **포트와 baudrate**: 이 IoT2022 버전은 `/dev/ttyUSB0`, **9600**. 01. Device 버전(ACM0, 115200)을 쓰면 안 된다.
- **포트 권한**: `sudo chmod 777 /dev/ttyUSB0` 실행.
- **Omniwheel_Protocol.py**: IoT2022 폴더에 없으면 `ModuleNotFoundError`. `01. Device\libraries`에서 복사.
- **연속 전송**: `time.sleep(1.0)`으로 명령 간격을 두지 않으면 버퍼가 밀릴 수 있다.

## 8. 실습 과제
1. 속도 시퀀스를 `[300, 0, -300, 0]`으로 바꿔 느린 동작을 확인하라.
2. X축만 0~600까지 50씩 증가시키며 속도 변화를 관찰하라.
3. Z축(회전)을 -400에서 400으로 왕복시키는 코드를 작성하라.
4. 모터 정지 후에도 명령을 계속 보내도록 루프를 수정해 보라.
5. `mid` 반복 순서를 Z→Y→X로 바꿔 구동 순서를 변경하라.
