# 1. LED 점멸 (PCA9685를 이용한 8채널 LED 순차 제어)

## 1. 학습 목표
- Jetson Xavier NX에서 I2C 버스를 초기화하는 방법을 이해한다.
- PCA9685 PWM 드라이버를 통해 LED의 ON/OFF를 제어하는 방법을 익힌다.
- `duty_cycle` 값이 LED의 밝기(출력 파워)를 결정한다는 원리를 이해한다.
- `for` 루프와 `time.sleep()`을 조합해 순차 점멸(켜기 → 끄기)을 구현한다.

### 1.1 배경 지식: PWM과 duty cycle
- **PWM(펄스 폭 변조)**: 일정 주파수에서 신호가 켜져 있는 시간(ON 폭)을 비율로 조절하는 방식. LED 밝기, 부저음, 모터 속도를 디지털 신호로 아날로그처럼 제어할 수 있다.
- **duty cycle(듀티비)**: 한 주기에서 신호가 HIGH인 시간의 비율. 0%면 항상 OFF, 100%면 항상 ON이다.
- PCA9685는 **12비트 해상도**를 가지므로 duty_cycle 값의 범위는 **0 ~ 4095**이다. 4095 ≈ 100%, 2048 ≈ 50%, 0 = 0%.
- 60Hz는 LED 점멸·서보 제어에 흔히 쓰는 PWM 기본 주파수이다. 주파수 60Hz = 1초에 60회 주기 반복.

## 2. 준비 사항
### 2.1 필요 하드웨어
- NVIDIA Jetson Xavier NX 보드 (JetPack 4.x)
- PCA9685 16채널 PWM 드라이버 모듈 (I2C 주소 0x40)
- 옴니휠 로봇 기판에 연결된 LED 8개 (PWM 채널 0 ~ 7)

### 2.2 필요 라이브러리 (설치 명령 포함)
```bash
sudo pip3 install adafruit-circuitpython-pca9685
```
- `busio`, `board` 라이브러리는 Adafruit CircuitPython의 기반 패키지로 함께 설치된다.
- 설치 후 I2C 권한 확인: `sudo chmod 777 /dev/i2c-*`
- 하드웨어 감지 확인: `sudo i2cdetect -y -r 1` 명령에서 **0x40**에 PCA9685가 표시되어야 한다.

### 2.3 사전 설정
- PCA9685의 SCL/SDA를 Jetson의 **SCL_1 / SDA_1** 핀에 연결한다.
  - 주의: 이 IoT2022 버전은 `board.SCL_1 / board.SDA_1`을 사용한다. 01. Device 버전의 `board.SCL / board.SDA`와는 다른 버스이므로 배선과 코드를 반드시 일치시킬 것.
- LED는 PCA9685의 채널 0~7에 각각 연결한다.
- 채널 번호는 회로도에서 실제 LED 연결 채널과 일치해야 한다.

## 3. 실행 방법 (셀 실행 순서 안내)
Jupyter Notebook에서 코드 셀을 실행한다.
1. `busio`, `board`, `adafruit_pca9685`, `time` 모듈 import
2. I2C 객체 생성 및 PCA9685 초기화, 주파수 60Hz 설정
3. 채널 0→7 순서로 0.5초 간격 LED 켜기 (duty_cycle = 4095)
4. 채널 8→0 역순으로 0.5초 간격 LED 끄기 (duty_cycle = 0)

위 흐름이 끝나면 8개 LED가 순차적으로 켜졌다가 역순으로 꺼지는 모습을 관찰할 수 있다. 다시 실행하려면 셀을 재실행하면 된다.

**단계별 예상 확인 포인트**
- 셀 실행 즉시 채널 0의 LED가 켜져야 한다. (아무것도 켜지지 않으면 배선·주소 문제)
- 0.5초마다 다음 채널이 켜져 4초 후 8개가 모두 켜진 상태가 된다.
- 이어서 역순으로 하나씩 꺼져 4.5초 후 모든 LED가 꺼진다.
- 실행이 끝나면 LED는 모두 꺼진 상태가 된다.

**중단 방법**: 실행 중 멈추려면 Jupyter 상단의 정지(■) 버튼을 누른다. 이 실습은 무한 루프가 아니므로 자연 종료된다.

## 4. 코드 해설 (원본 코드 그대로)
```python
import busio
import board
import adafruit_pca9685
import time
i2c = busio.I2C(board.SCL_1, board.SDA_1)
pca9685 = adafruit_pca9685.PCA9685(i2c)
pca9685.frequency = 60
for index in range(0, 8):
    pca9685.channels[index].duty_cycle = 4095
    time.sleep(0.5)
for index in range(8, -1, -1):
    pca9685.channels[index].duty_cycle = 0
    time.sleep(0.5)
```

**줄 단위 해설**
- `import busio`: I2C/UART 등 하드웨어 버스 통신을 지원하는 CircuitPython 모듈.
- `import board`: Jetson 보드의 핀 이름(`SCL_1`, `SDA_1`)을 정의하는 모듈.
- `import adafruit_pca9685`: PCA9685 PWM 드라이버 제어 모듈.
- `import time`: 지연 시간 제어용 모듈.
- `i2c = busio.I2C(board.SCL_1, board.SDA_1)`: SCL_1/SDA_1 핀으로 I2C 버스 객체 생성. 이 객체를 통해 모든 I2C 장치에 접근한다.
- `pca9685 = adafruit_pca9685.PCA9685(i2c)`: I2C 주소 0x40에 있는 PCA9685를 초기화한다.
- `pca9685.frequency = 60`: PWM 주파수를 60Hz로 설정. LED 점멸과 서보 제어의 기본 주파수.
- `for index in range(0, 8):`: index가 0부터 7까지 반복. 즉 채널 0~7.
- `pca9685.channels[index].duty_cycle = 4095`: 해당 채널의 duty_cycle을 4095(최댓값 = 100% ON)로 설정해 LED를 켠다. duty_cycle은 0~4095의 12비트 값.
- `time.sleep(0.5)`: 0.5초 대기하여 점멸 속도를 조절.
- `for index in range(8, -1, -1):`: index가 8, 7, ..., 0 순서로 감소하는 역순 루프.
- `pca9685.channels[index].duty_cycle = 0`: duty_cycle을 0(0% = OFF)으로 설정해 LED를 끈다.
- `time.sleep(0.5)`: 0.5초 대기.

**동작 요약**: 전방향(0→7)으로 켜고, 역방향(8→0)으로 끄는 시퀀스가 1회 실행된다. 채널 8은 LED가 연결되어 있지 않아 무해하지만, 실질적인 ON 루프는 0~7까지만 수행한다.

**동작 흐름 정리**
| 순서 | 루프 | 동작 | 대기 |
| --- | --- | --- | --- |
| 1 | `range(0, 8)` | 채널 0→7 LED 켜기 (duty 4095) | 0.5초씩 |
| 2 | `range(8, -1, -1)` | 채널 8→0 LED 끄기 (duty 0) | 0.5초씩 |

- `range(0, 8)`은 0,1,2,...,7을, `range(8, -1, -1)`은 8,7,...,0을 생성한다.
- 전체 실행 시간은 약 8×0.5 + 9×0.5 = 8.5초이다.

## 5. 원본 코드의 오타/수정 안내
이 노트북의 코드는 **오타 없이 정상 동작**한다. `range(8, -1, -1)`은 8부터 0까지 포함하므로 채널 0까지 정상적으로 꺼진다. (선택적으로 채널 8 대신 `range(7, -1, -1)`로 변경해도 동일한 동작을 보여준다.)

**학습 포인트 요약**
- I2C 초기화 → PCA9685 객체 생성 → 주파수 설정 → 채널 제어 순서를 기억한다.
- duty_cycle 4095(ON) / 0(OFF)이 이 실습의 핵심. 2번 실습(LED2)에서는 0~4095 사이 값으로 밝기를 조절한다.
- 이 실습이 동작하면 이후 모든 PCA9685 기반 실습(부저·서보·LED)의 기반이 확보된 것이다.
- `board.SCL_1/SDA_1`(IoT2022)과 `board.SCL/SDA`(01. Device)의 차이를 반드시 구분한다.

참고용 권장 수정(동작은 동일):
```python
for index in range(7, -1, -1):   # 8이 아닌 7부터 시작하는 것이 의미상 더 명확
    pca9685.channels[index].duty_cycle = 0
    time.sleep(0.5)
```

## 6. 실행 결과 예시
- 실행 후 터미널에는 별도 출력이 없다.
- 관찰 결과:
  - 채널 0→1→2→...→7 순서로 LED가 0.5초 간격으로 켜진다.
  - 이어서 채널 8→7→...→0 순서로 LED가 0.5초 간격으로 꺼진다.
- LED가 켜지지 않는다면 2.3의 SCL_1/SDA_1 배선과 채널 배선을 다시 확인한다.

**시간 흐름별 LED 상태 예시**
| 시간 | 켜진 LED |
| --- | --- |
| 0.0초 | 채널 0 |
| 0.5초 | 채널 0, 1 |
| 1.0초 | 채널 0~2 |
| 3.5초 | 채널 0~7 (전체 ON) |
| 4.0초 | 채널 0~6 (7 OFF) |
| 8.5초 | 전체 OFF (종료) |
- 모든 LED가 켜진 상태로 멈춰 있다면(꺼지지 않으면) 두 번째 for 루프의 `range(8, -1, -1)` 부분이 실행되지 않은 것이므로 들여쓰기(탭/공백)를 점검한다.
- 오류 메시지 `ValueError: Invalid SCL pin`이 나오면 `board.SCL/SDA`(01. Device 방식)로 변경해 배선과 맞춘다.

## 7. 주의사항 및 트러블슈팅
- **버스 번호 확인**: 코드는 `board.SCL_1/SDA_1` 기준이다. 만약 `ValueError: Invalid SCL pin` 같은 오류가 나면 `board.SCL/SDA`로 바꿔 확인한다.
- **I2C 주소 확인**: `sudo i2cdetect -y -r 1`(또는 0) 명령으로 0x40에 PCA9685가 검색되는지 확인.
  - 0x40이 보이지 않으면 배선(SCL_1/SDA_1, VCC, GND)과 모듈 전원(5V 권장)을 점검한다.
  - 주소가 0x40이 아닌 다른 값이라면 `adafruit_pca9685.PCA9685(i2c, address=0x??)`로 주소를 명시할 수 있다.
- **권한 문제**: I2C 접근 권한 오류가 나면 `sudo chmod 777 /dev/i2c-*` 또는 사용자를 i2c 그룹에 추가.
- **셀 중지**: 무한 루프가 아니므로 안전하지만, 셀 실행 중 멈추려면 Jupyter의 정지 버튼을 사용.
- **duty_cycle 범위**: 반드시 0~4095 사이여야 한다. 벗어나면 예외가 발생한다.
- **주파수 확인**: LED가 깜빡이거나 이상하게 보이면 `pca9685.frequency` 값이 너무 낮거나 높은 것은 아닌지 확인한다.
- **SCL/SDA 혼동 방지**: `board.SCL`/`board.SDA`(01. Device)와 `board.SCL_1`/`board.SDA_1`(IoT2022)은 서로 다른 핀이다. 배선과 코드가 일치하는지 반드시 확인한다.

## 8. 실습 과제
1. 켜는 순서를 7→0(역순)으로 바꾸고, 끄는 순서를 0→7(정순)으로 바꿔 실행해 보라.
   - 힌트: `range(7, -1, -1)`과 `range(0, 8)`을 서로 바꾸면 된다.
2. 점멸 간격을 0.1초 / 0.05초로 줄여 속도 변화를 관찰하라.
   - 힌트: `time.sleep(0.5)`의 값을 바꿔보고, 0.5보다 짧은 값에서 LED가 빠르게 점멸함을 확인한다.
3. `duty_cycle = 2048`(약 50%)로 설정하면 밝기가 어떻게 달라지는지 확인하라.
   - 힌트: 4095(100%)는 최대 밝기, 2048(50%)는 절반 밝기, 0은 꺼짐.
4. 모든 LED를 한꺼번에 켰다가 1초 후 모두 끄는 코드를 작성하라.
   - 힌트: `for` 루프 없이 `for index in range(8): ... duty_cycle = 4095`를 한 번에 실행하거나, 각 채널을 순회하며 설정한다.
5. LED 점멸 시퀀스를 5회 반복하도록 코드를 수정하라.
   - 힌트: 전체 블록을 `for repeat in range(5):`로 감싸면 된다.
